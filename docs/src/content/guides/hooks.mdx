Hooks provide a way to run arbitrary code at a given moment in your agent's life.

You can use hooks to cover setup that komra cannot handle out of the box, such as tearing down a docker stack, or configuring a network.

<Alert variant="danger">Do not use hooks to copy or link files, such as built dependencies, into a worktree. A [workflow](../workflows/#worktrees) already does that: its worktree copy paths and worktree symlink paths, `copy_paths` and `symlink_paths` on the [worktree config](../../api/workflow/create-workflow/#types), are copied or linked into every new worktree before the agent starts. Hooks are for what lives outside the tree.</Alert>

Hooks can also be used to clean up when an agent is destroyed. For instance, run a pre-delete hook to remove the network the agent needs.

## Writing a hook

Hooks are executable files in [`hooks.dir`](../../config/#hooks.dir), which is `~/.config/komrad/hooks` by default. Each hook runs inside its agent's directory.

In our example, Neovim keeps a `.git-blame-ignore-revs` file listing the commits that only reformatted code, so `git blame` can skip them. Git only honours the file when told to, and that setting lives in git's config rather than in the tree, so no checkout carries it. A hook can set it for each agent:

```sh
mkdir -p ~/.config/komrad/hooks
cat > ~/.config/komrad/hooks/ignore-revs <<'EOF'
#!/usr/bin/env bash
#KOMRAD description="make git blame skip neovim's reformatting commits"
git config blame.ignoreRevsFile .git-blame-ignore-revs
EOF
chmod +x ~/.config/komrad/hooks/ignore-revs
```

The `#KOMRAD` line is optional. A hook can declare a description and a timeout this way, in comment lines at the top of the file.

## Hanging it on a workflow

Press `e` on the workflow's row, move down to "Pre-launch hook", pick `ignore-revs`, and press `<C-s>`. Every agent spawned from now on runs it once its worktree exists and before its CLI starts.

## The moments

| Moment | Fires | Komrad waits | If it fails |
| --- | --- | --- | --- |
| `pre-launch` | Once the agent's directory exists, before its CLI starts. | Yes | The agent is not started and stays in the list marked as failed, so you can fix the cause and retry. |
| `post-launch` | Once the CLI is up, in the background. | No | The run's log says so. |
| `post-resume` | Once a dormant agent's CLI is back up, in the background. | No | The run's log says so. |
| `post-restore` | Once a restored agent's CLI is up, in the background. | No | The run's log says so. |
| `pre-teardown` | When an agent is deleted, before its worktree is removed. | Yes | The delete stops and the worktree is kept. |

Write `pre-teardown` so it is safe to run twice. Archiving does not run it.

Child agents run no hooks, because the directory they are in is not theirs.

## What a hook knows

Komrad tells a hook about its agent through environment variables. `KOMRAD_AGENT_ID` names the agent, `KOMRAD_AGENT_CWD` is its directory, `KOMRAD_TRIGGER` says which moment fired the hook, and `KOMRAD_ADDR` is where to reach the API. `KOMRAD_AGENT` holds the whole agent as JSON. `komrad` is on the hook's path, so it can ask the API anything else.

## When a hook fails

Every run writes its own log. When a hook fails, the error says so and the agent is marked as never having launched. Move the cursor onto the agent to see why.
