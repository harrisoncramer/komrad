# Development

The Go module is at the repo root, module name `claude-agents`. Everything is managed with mise, which pins the Go toolchain and every generator. The custom linter lives under `tools/`.

## Tasks

- `mise run go:build` builds the `bin/claude-agents` binary.
- `mise run go:dev` watches the `.go` files and rebuilds that binary on every save.
- `mise run go:reload` rebuilds the binary and kills the long-lived `serve` process so the next panel open respawns it. Reopen the popup to pick up panel changes too.
- `mise run go:test` runs every Go test.
- `mise run go:fmt` formats the code, `mise run go:tidy` tidies `go.mod`.
- `mise run go:lint` builds the custom golangci-lint with this repo's plugins if needed, then runs it with `--fix`.
- `mise run go:build-linter` rebuilds that custom linter binary.
- `mise run proto:generate` regenerates the Go and ConnectRPC code from `proto/`.
- `mise run db:migrate <name>` authors an Atlas migration by diffing `db/schema`.
- `mise run db:sqlc` regenerates the sqlc query bindings against the migrations.
- `mise run db:connect` opens a `sqlite3` shell to the database.
- `mise run gen-docs` regenerates the command reference under `docs/reference`.

## Live rebuild loop

The tmux plugin only builds `bin/claude-agents` when the binary is missing, so a plain code edit never reaches a running tmux. During development, keep `mise run go:dev` running in its own pane so the binary rebuilds on every save.

That task runs air, which watches the `.go` files and runs `go build -o bin/claude-agents .` on each save. Air's own process is a no-op (`bin = /usr/bin/true`), because the real binary is launched by the tmux popup, not by air. Nothing starts the watcher for you, so this is one manual step per dev session. Wire it into a tmux pane or a worktrunk enter hook if you want it automatic.

Rebuilding the file is not enough on its own. The panel runs in a popup that is spawned fresh from the binary each time you open it, so reopen the popup (prefix+g) after a save to pick up the new build. A popup that is already open keeps the old process. The status-bar segment shells out to `bin/claude-agents status` on tmux's own status interval, so it refreshes without any reopen.

## Generated code

Several trees are generated and must not be edited by hand.

The `proto/gen` tree is regenerated by `proto:generate` from `proto/proto`. The `db/models` tree is regenerated by `db:sqlc` from `db/queries`. The `docs/reference` tree is regenerated by `gen-docs` from the cobra command tree.

The reference generator, `docs/cmd/gen-docs`, walks the command tree and writes one markdown file per command using cobra's markdown doc support. Run `mise run gen-docs` after changing any command's name, short description, or flags so the checked-in reference stays in sync. It lives in its own module, `claude-agents/docs`, with a replace back to the repo root, so cobra's markdown dependencies never enter the root binary's module graph. The root `go.mod` stays limited to what the binary actually links.

The sqlc step has one wrinkle worth knowing. Atlas writes SQLite migrations with backtick-quoted identifiers, which SQLite accepts but sqlc's parser does not. The `db:sqlc` task concatenates the migrations with the backticks stripped into a throwaway `gen-schema.sql`, feeds that to sqlc for type inference, and leaves the migrations themselves as the single source of truth.

## Configuration in code

All configuration is read via ultra in the `config` package. The custom linter under `tools/agentslinter` enforces this with a `forbidgetenv` analyzer that fails the build on a direct `os.Getenv` call.
