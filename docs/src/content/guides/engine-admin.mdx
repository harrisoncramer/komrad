This guide is for whoever runs the remote engine. Using one that exists is covered in [running komrad remotely](../remote/). Everything here runs from a komrad checkout as a mise task, with AWS credentials in your environment.

## What gets built

The engine is one machine on AWS with a separate data disk and a managed Postgres. The machine is disposable. Everything that matters lives on the disk or in the database: conversations, worktrees, komrad's config, and the agent CLIs' logins. So the machine can be switched off or rebuilt without losing work.

The engine pushes code as a GitHub App rather than as you. The App's key is kept in AWS Secrets Manager and copied into memory at boot, so it never touches the disk.

## Standing one up

Do these in order.

1. Get an AWS account with a named profile, an S3 bucket for Terraform's state, and an SSH key used for nothing else.
2. Register a GitHub App with no webhook, installed only on the repositories the engine should work in, with read and write on contents, pull requests, issues and workflows. Store its private key in Secrets Manager as `komrad/github-app`, so the first boot finds it.
3. Build the machine image with `mise run packer:build`. It prints an image id at the end.
4. Copy the two example files in [`infra/engine`](https://github.com/harrisoncramer/komrad/tree/main/infra/engine) and fill them in: your account, region, the image id, your SSH key, and the addresses allowed in over SSH. Fill in the `github_*` values too, which let GitHub Actions deploy.
5. Run `mise run infra:engine:init` and `mise run infra:engine:apply`. It prints the engine's address.
6. Get a shell with `mise run remote:connect`. komrad's config at `~/.config/komrad/config.toml` already has a <Setting path="github_app" label="[github_app]" /> table pointing at the key. Fill in `app_id`, which is the App ID on the App's settings page, and `installation_id`, which is the number at the end of the address of the installation's Configure page.
7. Run `mise run remote:restart`. On the engine, <Command path="github token" /> should now print a token.
8. Point your panel at the engine as [running komrad remotely](../remote/) describes, and connect its forge through the App with `komrad forge connect github.com --method github-app --engine remote`.
9. On the engine, clone the repositories agents will work in onto the data disk over HTTPS, as in `git clone https://github.com/owner/repo`. The App's token only works over HTTPS, and a `git@github.com:` address is rewritten to it for you.
10. Still on the engine, set the name and email git commits under with `git config --global user.name` and `git config --global user.email`, then run `claude` once and log in.

The image takes care of the rest. Agents run with the permission flags that skip their CLI's prompts, and komrad trusts each agent's directory for the CLI before it starts. mise trusts every checkout under `/var/lib/komrad`, and the agent CLIs are installed outside mise, so a project that pins its own node version cannot hide them.

## Keeping it up to date

Publishing a release deploys it to the engine. A deploy restarts the service but leaves the agents running. You can also deploy by hand with `mise run remote:deploy`.

The machine image changes rarely. Building one from the Actions tab records it without applying it. `mise run remote:reimage` applies it, which replaces the machine and stops every agent. It names them and asks first.

The image writes komrad's config only the first time the data disk is set up, so a reimage leaves an existing engine's config as it was. When the image's defaults change, copy the ones you want from [`packer/files/komrad-config.toml`](https://github.com/harrisoncramer/komrad/tree/main/packer/files/komrad-config.toml) into the engine's config by hand.

## Keeping the bill down

`mise run remote:stop` switches the machine off and `mise run remote:start` switches it on. Every agent stops with it, but nothing else is lost. A GitHub Actions schedule does this every night, New York time. The disks and database are still billed while stopped, but the machine is most of the bill.

## Tearing it down

`mise run infra:engine:destroy` removes everything. The database is protected from deletion by default, so turn that off first. A final snapshot is kept.

That is everything a user or an operator needs. [How it works](../how-it-works/) starts the guides for anyone curious what is underneath.
