Komrad supports spawning or messaging agents on a schedule. This is useful for periodic work, such as triage work, or summarizer workflows.

Schedules fire on a cron expression and hand their prompts to an agent. They keep firing after you close the panel, as long as the engine is running.

<Alert variant="warning">This guide uses the `neovim` workflow from the [workflows](../workflows/) guide.</Alert>

There are two kinds of schedules: _implementer schedules_ launch a new agent each time, and _orchestrator schedules_ mail a running orchestrator.

## Implementer schedules

An implementer schedule launches a new agent into a workflow each time it fires, with the schedule's prompt. Everything else about the launch, such as the directory, the flags and the shared context, comes from the workflow at the moment it fires.

Open the schedules from the switcher at the top of the panel, open the menu with <Key name="menu.open" /> and press <Key name="schedule_menu.new" /> to write one. Leave the kind on implementer, then give it a name, a cron expression, a prompt, and the `neovim` workflow. The name also names every agent it launches.

The video uses `* * * * *` so the schedule fires within a minute.

An implementer schedule never piles up work. If an agent from its last run is still working or waiting on you, the next run is skipped and recorded as skipped.

## Orchestrator schedules

An orchestrator schedule mails its prompt to an orchestrator that is already running. Use it when the work belongs to an agent that already knows the workflow, such as asking the orchestrator each morning to hand out the day's work.

If the orchestrator is archived or deleted, the schedule's runs are cancelled. Edit it to point at another orchestrator, or archive it.

## Missed and paused runs

Komrad never catches up on missed runs. If the service is down when a run was due, that run is skipped. This is on purpose, so agents do not start at odd hours.

Runs that cannot succeed are cancelled with a reason, which shows as the schedule's last run. An implementer schedule whose workflow no longer exists is cancelled, for instance.

You can pause a schedule and arm it again later. A paused schedule keeps its settings.
