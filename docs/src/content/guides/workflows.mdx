Komrad agents run inside of _workflows_. Workflows are just a bucket of settings: the directory for an agent to run in, the harness it'll use, like Claude or Codex, and other settings for every agent that spawns within them.

<Alert variant="warning">This guide assumes you have [installed komrad](../install/) already.</Alert>

Think of a workflow a shared blueprint for every agent that does the same kind of work. Workflows control where agents start, which CLI they run, and what flags their agents use, like the `--dangerously-skip-permissions` flag for Claude.

Each workflow also has one _orchestrator_ agent, responssible for managing every _implementer_ agent within it. The orchestrator is created automatically alongside the workflow.

## Creating your first Workflow

Let's clone a real repository to work in. This guide uses Neovim:

```sh
git clone https://github.com/neovim/neovim ~/neovim
cd ~/neovim
```

Next, run <Command path="open" /> then open the menu with <Key name="menu.open" /> and press <Key name="menu.new_workflow" />, name the workflow `neovim` and press enter to create it. By default, your workflow takes the current directory as it's active directory:

The orchestrator writes no code of its own. You tell it what you want done, and it spawns agents into the workflow to do the work, passes messages between them, and gathers what they find. The orchestrator is the "brains" of every subagent that is doing real work and often stitches their work together or passes work between them.

You can learn more about the orchestrator and the other kinds of agent in the [agents](../agents/) guide.

## Shared context

Workflows can set _shared context_ for each implementer agent they create. This is where you put what you would otherwise tell each agent by hand: how tests run, how branches are named, and so forth.

In our Neovim example, that might be: "Run make lint before committing any Lua change."

The context is provided after your <Setting path="context">global context</Setting>, which every agent gets whatever workflow it is in. In the video below the global context says only that Neovim is the best editor, and the agent has read both.

## Worktrees

Like most agent orchestrators, komrad ships with first-class support for [worktrees](https://git-scm.com/docs/git-worktree).

When creating a workflow or an agent, tell komrad to automatically create a worktree for each task, and it'll cut one from the base branch. The agents on that task, its implementer and the reviewers it spawns, work within that worktree, isolated from other tasks. The worktree is automatically cleaned up when the task is deleted.

Komrad places worktrees into <Setting path="worktrees.dir" /> unless the workflow names its own location.

<Alert variant="info">
  Agents do not have to create worktrees, but be careful: those that don't will run directly inside of their parent
  directory.
</Alert>

## Archiving and restoring

Archiving a workflow puts it into cold storage: you can hard-delete it later, but for now, it'll be hidden from your workflow view. Open the menu on a workflow with <Key name="menu.open" /> and press <Key name="menu.archive" /> to archive it.

This doesn't delete the agent or it's wokflows. Instead, the agents inside of the workflow will be paused, and removed from the active agent list. If you want to resume their conversations later, you can restore them from the archive.

## Next Steps

You don't have to build your entire workflow right away.

Start with a directory and a worktree setting. Add context later. You can always have multiple workflows in the same directory, for instance, for different purposes like bugfixing or feature work.
