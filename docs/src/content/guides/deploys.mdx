## Deploying a build

`mise run remote:deploy` deploys your checkout's build to the engine, and `engine.yml` runs the same task in GitHub Actions.

The task builds komrad for the engine, uploads the binary to the Terraform state bucket and sends the instance a command through Systems Manager. On the instance, the command downloads the binary, stops the server, runs the credentials unit and starts the server again. The credentials unit runs the migrations, so they're in place before the new server starts. [The database](../engine-database/#credentials-on-komrads-engine) covers the credentials unit.

Agents keep running through a deploy, because stopping the server leaves tmux alone. [The machine](../engine-machine/#agents-during-server-restarts) explains how.

If the engine is stopped when a deploy runs, the deploy skips, since Systems Manager can't reach a stopped instance. The engine picks up those changes from the next deploy after it starts.

A panel connects only to an engine built from the same commit, and each deploy stamps the binary with its commit. If your checkout has uncommitted changes, the deploy stamps a `-dirty` version and also builds a panel to match at `dist/komrad-panel`.

To deploy a branch or tag without AWS credentials on your laptop, dispatch `engine.yml` from the Actions tab and pick the ref. It runs the full checks before it deploys. [Runbooks](../runbooks/#deploying-or-rolling-back) uses it for rollbacks.

## Image updates

Rebuild the image when a tool or a boot step changes, or when its system packages need updates. Dispatching `image.yml` builds an image and records its id in Systems Manager's parameter store, and leaves the running instance alone.

Applying an image replaces the instance, and that stops every running agent. `mise run remote:reimage` reads the recorded image id, lists the agents that will stop and asks before it goes on. It then writes the image id into your `terraform.tfvars` and applies. The data volume moves to the new instance and the database stays as it was, so you can resume the agents afterwards. The new instance also gets a new certificate, and Let's Encrypt issues at most five a week for the same name.

The image carries whichever komrad binary was current when it was built. If the engine should run something newer, deploy again after the reimage.
