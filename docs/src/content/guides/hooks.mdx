Hooks provide a way to run arbitrary code at a given moment in your agent's life.

You can use hooks to cover setup that komra cannot handle out of the box, such as tearing down a docker stack, or configuring a network.

<Alert variant="danger">
  Do not use hooks to copy or link files, such as built dependencies, into a worktree. A
  [workflow](../workflows/#worktrees) already does that: its worktree copy paths and worktree symlink paths,
  <Field message="workflow.v1.WorktreeConfig" name="copy_paths" /> and{" "}
  <Field message="workflow.v1.WorktreeConfig" name="symlink_paths" /> on the worktree config, are copied or linked into
  every new worktree before the agent starts. Hooks are for what lives outside the tree.
</Alert>

Hooks can also be used to clean up when an agent is destroyed. For instance, run a pre-delete hook to remove the network the agent needs.

## Writing a hook

Hooks are executable files in <Setting path="hooks.dir" />, which is `~/.config/komrad/hooks` by default. Each hook runs inside its agent's directory.

In our example, Neovim keeps a `.git-blame-ignore-revs` file listing the commits that only reformatted code, so `git blame` can skip them. Git only honours the file when told to, and that setting lives in git's config rather than in the tree, so no checkout carries it. A hook can set it for each agent:

```sh
mkdir -p ~/.config/komrad/hooks
cat > ~/.config/komrad/hooks/ignore-revs <<'EOF'
#!/usr/bin/env bash
#KOMRAD description="make git blame skip neovim's reformatting commits"
git config blame.ignoreRevsFile .git-blame-ignore-revs
EOF
chmod +x ~/.config/komrad/hooks/ignore-revs
```

The `#KOMRAD` line is optional. A hook can declare a description and a timeout this way, in comment lines at the top of the file.

## Hanging it on a workflow

Press <Key name="workflows.edit" /> on the workflow's row, move down to "Pre-launch hook", pick `ignore-revs`, and press `<C-s>`. Every agent spawned from now on runs it once its worktree exists and before its CLI starts.

## The moments

Every moment in an agent's life has a hook before it and a hook after it. Komrad waits for a `pre-` hook, and one that fails refuses the step. It never waits for a `post-` hook, and one that fails only marks its run.

| Moment         | Fires                                                      | If it fails                                                                                          |
| -------------- | ---------------------------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| `pre-launch`   | Once the agent's directory exists, before its CLI starts.  | The agent is not started and stays in the list marked as failed, so you can fix the cause and retry. |
| `post-launch`  | Once the CLI is up.                                        | The run's log says so.                                                                               |
| `pre-resume`   | Before a dormant agent's CLI starts again.                 | The agent is not resumed and stays dormant.                                                          |
| `post-resume`  | Once a dormant agent's CLI is back up.                     | The run's log says so.                                                                               |
| `pre-archive`  | While the CLI is still running, before its pane is closed. | Nothing in the archive call is archived.                                                             |
| `post-archive` | Once the pane is closed and the agent is in the archive.   | The run's log says so, and the agent stays archived.                                                 |
| `pre-restore`  | While the agent is still in the archive.                   | Nothing in the restore call is restored.                                                             |
| `post-restore` | Once the agent is back in the list, dormant.               | The run's log says so.                                                                               |
| `pre-delete`   | Once the panes are closed, before the worktree is removed. | The delete stops, the worktree is kept, and the agent is marked as failed to clean up.               |
| `post-delete`  | Once the worktree is removed and the agent's row is gone.  | Komrad's own log says so, since the agent has no run log left.                                       |

Anything an agent brought up that should not outlive it, such as a server or a database slot, belongs on `post-archive`. Put it on `pre-delete` as well, written so it is safe to run twice, to cover an agent deleted without being archived.

`pre-archive`, `pre-restore` and `pre-delete` are skipped when the agent's directory has already gone. `post-delete` runs in the hooks directory once the worktree is removed, and `KOMRAD_AGENT_CWD` still names where it was. An agent's hooks run one moment at a time, in the order the moments happened, and the worktree is not removed until they have all finished. So a hook should not archive, restore or resume its own agent, since that step waits for the hook that asked for it. A call that waits on a `pre-` hook, such as `archive_agents` from MCP or <Command path="rpc" />, is given eleven minutes rather than the usual thirty seconds.

Child agents run no hooks, because the directory they are in is not theirs.

## What a hook knows

Komrad tells a hook about its agent through environment variables. `KOMRAD_AGENT_ID` names the agent, `KOMRAD_AGENT_CWD` is its directory, `KOMRAD_TRIGGER` says which moment fired the hook, and `KOMRAD_ADDR` is where to reach the API. `KOMRAD_AGENT` holds the whole agent as JSON. <Command path="" /> is on the hook's path, so it can ask the API anything else.

## When a hook fails

Every run writes its own log. When a hook fails, the error says so and the agent is marked as never having launched. Move the cursor onto the agent to see why.
