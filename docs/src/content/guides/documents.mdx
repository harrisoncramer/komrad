Often, you'll want an agent to write down something that you can review outside of the codebase. For instance, you may want an implementer to write an RFC first, so that you can review it and fix it's approach.

Komrad suppports this natively. Komrad's _documents_ are markdown files that belong to an agent. Each is kept in komrad's database as one of the types you define, and komrad ships with RFC. A type's context tells agents how to write it, and you add or edit types from the documents view, where the [menu](../navigation/#the-agent-menu) over a type defines a new one with <Key name="document_types_menu.new" /> and edits it with <Key name="document_types_menu.edit" />. Komrad versions these documents, so you can step through their history.

## Agent-authored documents

Agents write documents with komrad's tools, so you ask for one in the prompt. Once it has written one, open the agent's [menu](../navigation/#the-agent-menu) with <Key name="menu.open" />, and jump to the documents view.

Other agents can read a document too. You can, for instance, have an orchestrator write an RFC and have another agent implement it.

Once the document says what you want, tell the agent to build it. It already has the document, so the prompt can be as short as "carry out truncate-rfc". The document stays with the agent, so later you can read it beside the diff and check that what was built is what you agreed on.

## Editing a document

Open the menu on a document with <Key name="menu.open" /> and pick edit with <Key name="document_menu.edit" /> to open it in your editor. When you quit, what you wrote is saved as the next version.

Komrad mails the agent to say you changed its document, and the agent can see exactly what you changed.

You can also start a document yourself from the same menu with <Key name="document_menu.new" />, such as a plan you wrote or notes the agent should keep in mind. The new document goes to the agent the filter names with `agent:`, so it is there whenever you open the documents from an agent's menu. Komrad tells the agent it exists.

## Stepping through versions

You can step back through a document's versions. Each step shows what that version changed, who wrote it, and when. After a round or two it shows what the agent first proposed, what you changed, and how the agent answered.

## Filtering documents

Press `/` on the documents view to filter it. Plain words match the document's name, and these qualifiers narrow it further.

| Qualifier       | Keeps the documents                                        |
| --------------- | ---------------------------------------------------------- |
| `agent:NAME`    | written by an agent whose name contains NAME               |
| `workflow:NAME` | written by an agent in a workflow whose name contains NAME |
| `type:NAME`     | of the type NAME                                           |
| `since:WHEN`    | changed at or after WHEN, such as `2d` or `2026-10-01`     |
| `until:WHEN`    | changed up to WHEN, a day counting in full                 |

Quote a name that holds a space.
