A local review is how you read what an agent wrote and tell it what to change. You read the diff in the panel, leave comments on its lines, and send them all at once. The agent gets them as mail and answers in the same threads.

None of this touches GitHub or GitLab. The review lives in komrad beside the agent, so you can read and comment on work long before anyone opens a pull request. Reviewer agents use the same threads, so their comments and yours sit in one place.

<Alert variant="warning">
  This guide uses the `neovim` workflow from the [workflows](../workflows/) guide. The videos follow one agent adding
  `vim.text.truncate()` to Neovim, which you have reviewed twice and a reviewer agent has reviewed once.
</Alert>

## Opening a review

Put the cursor on an agent and press <Key name="agents.review" />, or pick review from its [subpages](../navigation/#subpages). The diff fills the stage, showing everything the agent changed since its branch left the base. The sidebar shows the conversation on the line under the cursor, and the band above it names the agent, the size of the change, and how much of it you have already read.

You move through the diff like any other list, and the legend under the sidebar lists the rest. It can jump from file to file, from one thread to the next, or to the comments nobody has settled yet. You can fold a file away once you have read it, and it stays folded until the agent touches it again.

The agents list keeps count between visits. Each agent shows its open and settled comments, the reviewer agents' first and yours second, and marks a thread the agent has answered that you have not read yet.

## Leaving comments

Press <Key name="review.compose" /> on a line to comment on it, or on a line that already has a thread to reply there. The row above the first file takes a comment about the work as a whole.

A saved comment is a draft that nobody else sees. You can read the whole change, change your mind, and send everything together. While you hold drafts the diff stays still, so the lines you are commenting on do not move underneath you. The band says when the agent has written more, and you catch up when you are ready.

## Editing the code yourself

Sometimes fixing a line is quicker than describing the fix. Press <Key name="review.edit_file" /> to open the file in your editor beside the diff. Komrad pauses the agent while you edit, since you are both working in its checkout. When you close the editor the agent carries on from your change, and your drafts are still there.

## Sending

When you are done reading, send the review. Komrad asks if you have anything to say about the work as a whole, then sends it. You can also interrupt the agent so it reads your comments now rather than when it finishes what it is doing.

## Answers

The agent answers in your threads. A plain reply is a question or a disagreement. An answer that says the change is made settles your comment, and from that comment you can see exactly what the agent changed to answer it. You can settle or reopen any comment yourself.

## Stepping through history

Each review you send closes a chapter, which is the work you had read when you sent it. Stepping back from all changes shows the newest work first, the part nobody has reviewed. Each step after that shows the work between two of your reviews, with the comments as they stood then. Stepping forward brings you back to all changes.

This is how you follow a long change one pass at a time. Past chapters are only for reading, since their lines may no longer exist in the agent's work.

## Reviews from agents

An agent can ask for a review of its own work. Komrad starts a reviewer agent in the same worktree, which comments and sends the way you do. The difference is that a reviewer agent approves or requests changes with each review, while yours carry comments only.
