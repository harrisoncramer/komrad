This site is static. Astro builds it, a private S3 bucket holds it, and CloudFront serves it at komrad.dev. It has nothing to do with running an engine, and an engine never needs it.

## Versions

Every build lives under a prefix of its own in the bucket. `latest/` follows main, and each release adds a prefix named after its tag, such as `v0.4.0/`. A `versions.json` file at the bucket root lists them for the site's version picker.

A request function on CloudFront decides what each request gets:

- A request for `www.komrad.dev` or any other name goes to `komrad.dev` with a permanent redirect.
- A request for `/` goes to `/latest/`.
- A request for a directory gets that directory's `index.html`, since a private bucket has no index pages of its own.

## Domains and certificates

Cloudflare holds DNS for every domain. The certificate comes from AWS Certificate Manager, which Terraform validates by writing records into Cloudflare. komrad.ai, komrade.app and komrade.dev redirect to komrad.dev through Cloudflare's redirect rules, and never reach AWS.

## Publishing

`docs-deploy.yml` publishes `latest` on any push to main that touches the docs, their tasks, or their infrastructure. The release workflow calls it with the tag to publish that version.

The workflow assumes the `AWS_DOCS_CI_ROLE` role, which trusts only main and version tags. That role can write the bucket and clear CloudFront's cache, and nothing on the engine.

To publish by hand, run `mise run docs:deploy latest`, or name a version.

The panel recordings the guides play live apart from any version, under `media/` in the bucket. `mise run docs:recordings` records them against a throwaway instance, and `mise run infra:docs:recordings upload` publishes them. A recording keeps its address when it is redone, so every version of the docs shows the newest one.

## Infrastructure

The Terraform lives in [`infra/docs`](https://github.com/harrisoncramer/komrad/tree/main/infra/docs) and keeps its state in the same bucket as the engine's. It reuses the GitHub trust the engine stack creates, so apply that one first. Run `mise run infra:docs:init`, then `mise run infra:docs:apply`. The apply needs `CLOUDFLARE_API_TOKEN` in your environment, with permission to edit DNS and redirect rules on each domain.
