Some work is worth doing on a timer, such as a nightly pass over the lint, a summary of what changed each morning, or a nudge to your orchestrator before you sit down. Schedules do this.

A schedule fires on a cron expression and hands its prompt to an agent. It lives in komrad's database, so it keeps firing after you close the panel. There are two kinds: implementer schedules launch a new agent each time, and orchestrator schedules mail one that is already running.

<Alert variant="warning">This guide uses the `neovim` workflow from the [workflows](../workflows/) guide.</Alert>

## Implementer schedules

An implementer schedule launches a new agent into a workflow each time it fires, with the schedule's prompt. Everything else about the launch, such as the directory, the flags and the shared context, comes from the workflow at the moment it fires.

Press `O` then `s` to open the schedules, and `c` to write a new one. Leave the kind on implementer, give it a name, a cron expression and a prompt, and pick the `neovim` workflow. Submit it with `<C-s>`. The name also names every agent it launches.

The video uses `* * * * *` so the schedule fires within a minute. A nightly run would be `0 2 * * *`.

An implementer schedule never piles up work. If an agent from its last run is still working or waiting on you, the next run is skipped and recorded as skipped. A schedule that fires often can also hide its runs, so they do their work without taking a row in the agents list.

## Orchestrator schedules

An orchestrator schedule mails its prompt to an orchestrator that is already running. Use it when the work belongs to an agent that already knows the workflow, such as asking the orchestrator each morning to hand out the day's work.

The form is the same, except you pick the orchestrator kind and then the orchestrator to mail. That kind is only offered while at least one orchestrator is running. The mail is signed with the schedule's name, and the orchestrator reads it as coming from you.

If the orchestrator is archived or deleted, the schedule's runs are cancelled. Point it at a new orchestrator with `e`, or archive it with `z`.

## Missed and paused runs

Komrad never catches up on missed runs. If the service is down when a run was due, that run is skipped. This is on purpose, so agents do not start at odd hours.

Runs that cannot succeed are cancelled with a reason, which shows as the schedule's last run. An implementer schedule whose workflow no longer exists is cancelled, for instance.

Press `space` on a schedule to pause it, and again to arm it. A paused schedule keeps its settings and fires again once armed.
