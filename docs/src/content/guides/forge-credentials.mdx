Agents push branches, and komrad reads pull requests, so an engine needs credentials for every forge it works with. On your laptop your own token is fine. On a machine other people use it isn't, because every agent would push as you, and your token would sit on a disk somewhere for as long as it's valid. So our engine gets an identity of its own, with tokens that expire on their own.

## GitHub

On GitHub the engine acts as a GitHub App. An App has a private key, and the key lets the engine ask GitHub for a token that lasts an hour and only reaches the repositories the App is installed on. Git asks komrad for a token each time it pushes, komrad mints a fresh one, and nothing long-lived ever gets written down.

To set it up, register an App with no webhook, give it read and write on contents, pull requests, issues and workflows, and install it on just the repositories the engine should work in. Then store its private key in AWS Secrets Manager as `komrad/github-app`, as JSON with the key under `private_key`. The machine pulls the key into memory when it boots, so it never touches the data volume or an image.

The engine's config needs the App's id, its installation id and where to find the key. <Command path="github token" /> should print a token once that's right. Then point komrad's own forge connection at the App with <Command path="forge connect" args="github.com --method github-app --engine remote" />.

## GitLab

GitLab has nothing like a GitHub App, so the engine uses a personal access token that komrad keeps rotating. Connect it with <Command path="forge connect" args="gitlab.com --method rotating-token" />, piping in a token with the api scope. Komrad rotates it straight away, so the token you pasted stops working, and then rotates it again every day.

The image already tells git to ask komrad for gitlab.com tokens. A self-hosted GitLab needs one more line, run as root on the machine:

```sh
git config --system credential.https://git.example.com.helper '!komrad gitlab credential'
```

## Rotating the App key

Now and then you'll want a new key for the App. Generate one in the App's settings, put it in the secret, and get the machine to read it again, as [runbooks](../runbooks/#rotating-the-github-app-key) shows. Once the engine is using the new key, delete the old one from the App.
