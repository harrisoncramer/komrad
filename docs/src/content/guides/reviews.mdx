Komrad supports providing feedback to agents directly in code rather than via a forge like Github or Gitlab. This helps keep feedback loops quick and reduce CI spend for agent-authored changes.

With local reviews, you can read the agent's diff, leave comments on its lines, and edit it yourself. The agent will respond in the same view.

Komrad's local review model is quite similar to how <a href="https://www.gerritcodereview.com/">Gerrit</a> does code review, where you can step through chunks of changes (known in komrad as chapters) that correspond to review rounds. Each chapter is tied to a specific diff in the code that an agent has made. Using local reviews is completely optional.

  This guide uses the `neovim` workflow from the [workflows](../workflows/) guide. The videos follow one agent adding

## Opening a review

Put the cursor on an agent, press <Key name="subpages.open" /> to open its [subpages](../navigation/#subpages), and pick review with <Key name="subpages.review" />. The main panel then shows everything the agent changed since its branch left the base. The sidebar shows conversations.

The agents list keeps count between visits. Each agent shows its open and settled comments at the right end of its row, a robot before the reviewer agents' and a person before yours, and marks a thread the agent has answered that you have not read yet.

## Leaving comments

Press <Key name="review.compose" /> on a line to comment on it, or on a line that already has a thread to reply there. The row above the first file takes a comment about the work as a whole.

The draft is not submitted to the agent until you submit the entire review. Take your time to read the change. While you hold the drafts, the diff is "frozen", so the lines you are commenting on do not move.

## Editing the code yourself

Sometimes fixing a line is quicker than describing the fix. Press <Key name="review.edit_file" /> to open the file in your editor beside the diff. Komrad pauses the agent while you edit, since you are both working in its checkout. When you close the editor the agent carries on from your change, and your drafts are still there.

## Sending

When you are done reading, send the review. Komrad asks if you have anything to say about the work as a whole, then sends it. You can also interrupt the agent so it reads your comments now rather than when it finishes what it is doing.

The agent gets one piece of mail. Each comment comes with the lines it was written on and the code around them, so the agent can find the spot even after the file has moved.

The agent answers in your threads, and can settle them. You can even press see exactly what the agent changed to answer the comment with <Key name="review.answer" /> . You can settle or reopen any comment yourself.

## Stepping through history

Each review you send closes a "chapter" in komrad, which holds the work you had read when you sent it. Stepping through chapters shows each review, with the comments as they stood then and the code that changed as a result.

Past chapters are read-only, since their lines may no longer exist in the agent's work.

## Local review from agents

An agent can ask for a review of its own work.

Komrad starts a reviewer agent in the same worktree, which comments and sends the way you do. Reviewer agents approve or requests changes with each review.
