Postgres holds every record an engine keeps, including the list of people who may use it. Komrad connects with three different logins, and each one can do only what its job needs.

## Database logins

<figure>
  <img
    src={link("/diagrams/engine-database.png")}
    alt="Migrate, ensure and grant connect as the owner login, which owns the schema. The server connects as the engine login, and the MCP query tools as the reader login. Both reach only one engine's rows."
  />
</figure>

The owner login owns the schema. <Command path="migrate" />, <Command path="engine ensure" /> and the grant commands connect as the owner, and the server never does.

The server runs as the engine login, which <Command path="engine ensure" /> creates for each engine. Postgres row-level security limits that login to its own engine's rows, so several engines can share one database without seeing each other's data.

The reader login sees the same rows as the engine login and can't write any of them. When an agent queries the database through komrad's MCP tools, the query runs as the reader.

## Credentials on komrad's engine

RDS creates the owner login and stores its password in Secrets Manager. The machine reads the secret each time it needs the owner, and it never writes the password to disk.

The credentials unit runs at boot, during every deploy and once an hour. Each run migrates the database, makes sure the engine login exists, and writes the server's connection string to a file only root can read. Because the unit runs during deploys, new migrations land before the new server starts. The hourly run picks up the owner's new password after RDS rotates it.

## Backups

RDS keeps automatic backups for seven days. Deletion protection is on, and Terraform refuses to destroy the database until you turn it off, as [runbooks](../runbooks/#tearing-it-down) shows.
