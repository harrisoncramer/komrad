Let's say you want to spawn an agent every day at 10am, which reads overnight alerts and writes up a summary for you. You can do this with schedules.

Schedules spawn one implementer agent into a workflow on the timing you specify. The launch details, aside from the prompt, still come from the workflow each time the schedule fires. Think of schedules of a way to spawn implementer agents automatically with a pre-defined prompt. Schedules live in komrad's database, so they survive application restarts.

To create one, press `S` to open the schedules screen, then press `c` to create one.

## How schedules work

Komrad never catches up on missed runs. If the service is down when a run was due, that run is skipped. This is intentional, to avoid accidental agents running at odd hours.

Furthermore, a schedule never piles up work. If an agent from its last run is still working or waiting on you, the next run is skipped and recorded as skipped. Plan accordingly.

Runs that cannot succeed are cancelled with a reason. For instance, if a schedule is told to spawn an implementer agent into a workflowk, but that workflow no longer exists, the schedule will fail.

You can pause a schedule, which prevents it from spawning new agents.
