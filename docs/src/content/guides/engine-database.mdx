Postgres holds every record an engine keeps: workflows, tasks, agents, mail, reviews, transcripts, and who may use the engine. Komrad connects to it with three logins, and each login can do only what its job requires.

## Database logins

<figure>
  <img
    src={link("/diagrams/engine-database.png")}
    alt="Migrate, ensure and grant connect as the owner login, which owns the schema. The server connects as the engine login, and the MCP query tools as the reader login. Both reach only one engine's rows."
  />
</figure>

The owner login owns the schema. <Command path="migrate" />, <Command path="engine ensure" /> and the grant commands use it. The server never does.

The engine login is the one the server runs as. <Command path="engine ensure" /> creates it for each engine. Postgres row-level security limits it to that engine's rows, so several engines can share one database without seeing each other's data.

The reader login sees the same rows as the engine login, but it can't write. Agents' database queries through komrad's MCP tools run as the reader, so they can't change any data.

## Credentials on our engine

RDS creates the owner login and keeps its password in Secrets Manager. The machine never stores that password on disk. It reads the secret each time it needs the owner.

The credentials unit runs at boot, on every deploy, and every hour. Each run migrates the database, makes sure the engine login exists, and writes the server's connection string to a file only root can read. Running on every deploy applies new migrations before the new server starts. Running hourly picks up the owner's new password after RDS rotates it.

## Backups

RDS keeps automatic backups for seven days. Deletion protection is on, so Terraform can't destroy the database until you turn it off. [Runbooks](../runbooks/#tearing-it-down) covers that.
