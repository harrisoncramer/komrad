Agents push branches and komrad reads pull requests, so an engine needs credentials for each forge. On a laptop your own token is fine. On a machine several people use, a personal token would make every agent act as you, and it would sit on a disk for as long as it is valid. Our engine uses credentials that belong to the engine and expire on their own.

## GitHub

The engine acts as a GitHub App. An App has a private key, and the key signs a short request that GitHub trades for a token lasting an hour. That token can reach only the repositories the App is installed on.

Register the App with no webhook, and install it only on the repositories agents should work in. Give it read and write on contents, pull requests, issues and workflows. Store its private key in Secrets Manager as `komrad/github-app`, as JSON:

```json
{ "private_key": "-----BEGIN RSA PRIVATE KEY-----\n..." }
```

At boot the machine copies the key to `/run/komrad/github.pem`. That path is in memory, so the key never reaches the data volume or an image, and each boot fetches it again. An engine with no such secret still boots, but it has no GitHub identity and can't push.

Komrad finds the key through the <Setting path="github_app" label="[github_app]" /> table in its config, which names the App's id, its installation id and the key's path. <Command path="github token" /> prints a fresh token, which proves the table is right.

Git gets its token from <Command path="github credential" />, which the image sets as the system-wide credential helper for github.com. Each push asks for a token and the helper mints one, so no token is ever stored.

Komrad's own forge connection uses the App as well. <Command path="forge connect" args="github.com --method github-app" /> tells the server to mint its tokens from the App, and it records the App's name as the login. Run it on the engine, or from your laptop with `--engine` naming the engine.

## GitLab

GitLab has no Apps, so the engine uses a token that rotates. Connect it with <Command path="forge connect" args="gitlab.com --method rotating-token" />, piping in a personal access token with the api scope. The server rotates it at once, so the token you pasted stops working, and rotates it again every day before it expires.

Git gets the current token from <Command path="gitlab credential" />. The `glab` komrad puts on an agent's path reads it through <Command path="gitlab config" />, in a config that names that host alone.

The image sets up the helper for gitlab.com. A self-hosted GitLab needs a line of its own, run as root:

```sh
git config --system credential.https://git.example.com.helper '!komrad gitlab credential'
```

## Rotating the App key

Generate a new key in the App's settings and put it in the secret. The machine reads the key only at boot, so either reboot it or rerun the unit as root, as [runbooks](../runbooks/#rotating-the-github-app-key) describes. Then delete the old key from the App.
